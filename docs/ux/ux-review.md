# UX Review

This document reviews Fenéla from the user's perspective.

Fenéla is designed for moments when the user feels overwhelmed. The UX should reduce cognitive load. It should not add more pressure, more decisions or more explanation than needed.

## Core UX question

Every screen and flow should support one question:

```text
What is one small thing I can do next?
```

If a screen does not help the user move toward that answer, it should be simplified, postponed or removed.

## UX principles

Fenéla should feel:

- calm;
- simple;
- human;
- low-pressure;
- predictable;
- easy to understand;
- easy to leave and return to.

Fenéla should not feel:

- demanding;
- clinical;
- gamified;
- productivity-heavy;
- emotionally manipulative;
- full of choices;
- dependent on AI.

## Core loop review

Fenéla is built around this loop:

```text
overwhelm -> one small action -> gentle accountability -> daily return
```

### Overwhelm

The user may arrive with low energy, stress or mental clutter.

UX requirement:

- avoid long explanations;
- avoid complex setup;
- avoid unnecessary choices;
- use calm copy;
- make the next step obvious.

### One small action

The product should help the user reduce a vague or large intention into one small action.

UX requirement:

- keep the input focused;
- avoid multi-step planning;
- avoid task systems;
- keep the anchor concrete;
- make completion feel reachable.

### Gentle accountability

Accountability should support the user without pressure.

UX requirement:

- reminders must be optional;
- notification permission must not block the app;
- copy should avoid guilt or urgency;
- the user should remain in control.

### Daily return

The app should be easy to return to.

UX requirement:

- keep the flow familiar;
- avoid adding new concepts too quickly;
- make the anchor easy to understand later;
- do not turn daily return into a streak system.

## Onboarding and screening

The onboarding and screening flow should help the app understand enough to support anchor creation.

It should not become a long intake, diagnosis flow or coaching questionnaire.

Current UX boundary:

- screening may ask relevant questions;
- questions should stay practical;
- the flow should not feel clinical;
- the user should not need expert language;
- the result should support one anchor, not a full life plan.

## AI assistance

AI should feel like optional support, not the center of the app.

Good AI behavior:

- suggests smaller actions;
- rephrases unclear input;
- uses calm and practical language;
- avoids inflated advice;
- keeps the user in control.

Bad AI behavior:

- gives medical or therapeutic advice;
- acts like a therapist;
- creates complex plans;
- over-explains;
- makes the user feel dependent on AI;
- turns one anchor into a productivity system.

## Reminder flow

Reminders should be offered as gentle support.

The user should be able to continue without reminders.

UX requirements:

- do not block onboarding if reminders are declined;
- make “continue without reminders” clear;
- avoid pressure-based copy;
- explain browser permission only when needed;
- keep reminder choices simple.

## Cognitive load risks

Potential UX risks:

- too many questions;
- unclear AI role;
- reminder permission friction;
- too much explanation;
- product language that sounds too clinical;
- turning Fenéla into a planner;
- adding features because they are technically possible.

Mitigation:

- keep the core loop visible in product decisions;
- remove features that do not support one small action;
- keep optional features optional;
- write copy in plain language;
- test whether the flow still feels calm.

## Accessibility considerations

Fenéla should be accessible enough for a simple public MVP.

Current focus:

- readable text;
- clear button labels;
- simple navigation;
- low visual noise;
- no unnecessary animations;
- predictable interaction flow.

Possible accessibility improvements:

- keyboard navigation review;
- color contrast review;
- screen reader pass;
- reduced-motion review;
- clearer error states.

These are quality improvements, not product-scope commitments.

## Copy principles

Fenéla copy should be:

- short;
- concrete;
- calm;
- non-clinical;
- non-judgmental;
- focused on the next step.

Avoid copy such as:

```text
Transform your life today.
```

```text
Never fail your habits again.
```

```text
Your AI therapist is here.
```

Prefer copy such as:

```text
Choose one small action.
```

```text
You can come back to this later.
```

```text
Continue without reminders.
```

## MVP UX verdict

The current MVP direction is appropriate if it stays focused on:

- one anchor;
- optional AI support;
- optional reminders;
- simple return behavior;
- no heavy dashboard;
- no clinical positioning.

The main UX risk is scope creep.

## UX decision

Decision:
Fenéla should prioritize calm completion over feature depth.

Reason:
The user is likely arriving with cognitive load already high. More features can make the product less useful.

Trade-off:
The app may feel smaller than productivity tools with dashboards, streaks and analytics.

Impact:
The UX remains easier to understand, easier to maintain and more aligned with the product purpose.

## Summary

Fenéla should help the user move from overwhelm to one small next action.

The UX is successful when the next step is clear, small and possible without adding extra pressure.
